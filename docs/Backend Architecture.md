Backend Architecture (Laravel 13)The backend strictly adheres to a separated-layer architecture to ensure maintainability and testability.
1. Request FlowRoute ➔ Middleware (Sanctum) ➔ Policy (Spatie) ➔ Form Request (Validation) ➔ Controller ➔ Service (Business Logic) ➔ Eloquent Model ➔ Controller ➔ API Resource ➔ Unified JSON Response
2. Layer ResponsibilitiesControllers: Kept as thin as possible. Their only job is to inject the FormRequest, call the appropriate Service method, and format the output using an API Resource.Services (app/Services): The heart of the application. All business logic, calculations, and complex database writes belong here. Use DB::transaction(function () { ... }) for operations touching multiple tables (like ending an old assignment and creating a new one).Form Requests (app/Http/Requests): Handle 100% of input validation. Ensure validation error messages utilize localization keys.Policies (app/Policies): Map directly to Spatie Permissions to authorize whether a user can perform an action on a model.API Resources (app/Http/Resources): Transform Models to arrays. Use ResourceCollection for lists. Conditionally load relationships using $this->whenLoaded('relationName') to prevent N+1 issues.

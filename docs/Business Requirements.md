Business RequirementsCore ModulesAuthentication & RBAC: Secure access based on system-level roles (super_admin, employee).Departments: Management of internal company departments.Application Types: Dynamic categorization of IT assets (e.g., API, Web Portal, Mobile App, Microservice).Vendors: Registry of external service providers.Users (Employees/Contractors): Central user directory.App Roles: Dynamic definitions of roles applicable within an application (e.g., Support, Developer, QA).Applications: The IT asset inventory.Application Assignments: The mapping engine connecting Users to Applications with specific App Roles.Core Business RulesA User can be internal (no vendor attached) or belong to exactly one Vendor.A User can be assigned to multiple Applications.An Application can have multiple Users assigned to it.A User's role is Application-Specific. (e.g., User A is "Admin" on App 1, but "Tester" on App 2).Historical Tracking (Audit): An Assignment is not a simple override. If a user's role on an application changes, the existing assignment must be explicitly closed (ended_at = now()), and a new assignment record is created.A user cannot have two open assignments for the exact same application simultaneously.
